# Соответствие бэкенда макету

Источник: [Figma, библиотечная система записи](https://www.figma.com/design/pz4Rze3coa3cPPtJVGpGvf/Untitled?node-id=0-1). Требования прочитаны из текстовых слоёв макета 13 октября 2026 года.

| Сценарий макета | Реализация API |
|---|---|
| Афиша и карточка события | `/events`, `/events/{id}`, `/branches`, `/categories`; описание, программа, возраст, постер, даты, филиал |
| Имя и фамилия, email, пароль, согласие | `/auth/register`, `/consent` |
| Вход и личный кабинет | `/auth/login`, `/auth/me`, `/bookings` |
| Одно место на одного читателя, бесплатно | `seats=1`; уникальная активная бронь на пару читатель/событие; тарифов нет |
| Свободно = вместимость − подтверждённые брони | Расчёт остатка и блокировка строки мероприятия при изменениях |
| Места закончились во время входа | Повторная проверка при создании брони, ответ `409` |
| Отмена с возвратом места, сохранение истории | `/bookings/{id}/cancel`; повторная отмена не меняет остаток |
| Отмена сотрудником с причиной | `/admin/events/{id}/status`; статус брони `event_cancelled`, причина в кабинете |
| Черновик, публикация, закрытие, завершение, отмена | Проверяемые переходы статусов события |
| Нельзя уменьшить вместимость ниже активных броней | Проверка под той же блокировкой мероприятия |
| Сотрудник работает со своим филиалом | `staff.branch_id`; фильтрация списка и проверка каждого защищённого действия |
| Участники, посещение, выгрузка | `/participants`, `/attendance`, `/participants/export`; посещение отдельно от статуса |

Телефон необязателен и добавлен для возможного контакта сотрудника с читателем. В макете форма регистрации содержит имя, email и пароль. Поля «повторите пароль», сохранение выбора при входе и подтверждение отмены относятся к фронтенду; фронтенд здесь не создаётся.

Из проекта бара перенесён подход FastAPI + PostgreSQL + SQLAlchemy + валидация + транзакции, а не его таблицы или реальные данные. `table_number`, выбор почасового интервала, тарификация, Telegram/VK-идентификаторы, боты и уведомления заменены сущностями `Branch`, `Event`, `User`, `Booking` и `AuthSession`.

Администратор с общим доступом нужен для первоначальной настройки филиалов и не выдаётся при публичной регистрации. Пользовательские сотрудники получают доступ ровно к назначенному филиалу.
