# Library Booking Backend

Бэкенд сайта записи на бесплатные мероприятия библиотеки для дипломного проекта и практики. Адаптирован из системы бронирования бильярдных столов: сохранены FastAPI, PostgreSQL, SQLAlchemy и транзакционная проверка доступности; предметная область заменена на мероприятия и читателей.

Работа выполнена по [макету в Figma](https://www.figma.com/design/pz4Rze3coa3cPPtJVGpGvf/Untitled?node-id=0-1). Репозиторий содержит только серверную часть. Фронтенд, Telegram/VK-боты, оплата и почасовые тарифы отсутствуют.

## Возможности

- Регистрация по имени, email и паролю; согласие с сохранением текста, версии и времени принятия.
- Вход, текущий профиль, выход с отзывом сессии. Пароли хранятся в виде Argon2-хешей; в базе сохраняются только хеши токенов сессий.
- Афиша: поиск, фильтры по филиалу, категории, датам и доступности; карточка события с программой, возрастной маркировкой и остатком мест.
- Один читатель бронирует одно место. Повторная активная запись на то же событие запрещена.
- Личный кабинет: предстоящие записи и история. Отмена до начала события возвращает место. Можно записаться заново.
- Сотрудник управляет событиями и участниками своего филиала: черновик, публикация, закрытие записи, завершение, отмена с причиной.
- Посещение учитывается отдельно от статуса брони. Участников можно выгрузить в CSV.
- Администратор первоначально создаёт филиалы; права сотрудника назначаются локальной командой.
- API с интерактивной документацией Swagger, миграции базы и автоматические тесты.

## Стек

Python 3.12+, FastAPI, SQLAlchemy Async, PostgreSQL 16+, Alembic, Pydantic, pwdlib/Argon2. Docker необязателен: это дополнительный способ запуска приложения и базы.

## Запуск без Docker

Установите Python 3.12+ и PostgreSQL 16+. В PostgreSQL создайте **нового пользователя `library` и отдельную базу `library`**, принадлежащую этому пользователю. База проекта бара не используется.

Из корня этого репозитория, в PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/init_env.py
```

Откройте созданный `.env` и замените `DATABASE_URL` строкой подключения к вашей новой базе. Например:

```dotenv
DATABASE_URL=postgresql+asyncpg://library:your-password@localhost:5432/library
```

Укажите фактический пароль пользователя PostgreSQL. Специальные символы в пароле строки URL должны быть URL-кодированы. Генератор `.env` создаёт пароль из букв и цифр, но при запуске без Docker пароль пользователя PostgreSQL задаётся отдельно.

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m app.cli seed-demo
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

Документация: **http://localhost:8002/docs**. Проверка базы: **http://localhost:8002/health**. Пример `seed-demo` добавляется только в пустую базу и явно помечен демонстрационным; команда необязательна.

Если установлена другая поддерживаемая версия Python, замените `py -3.12` на её команду запуска. В Linux/macOS используется `python3` и `.venv/bin/python`.

## Запуск с Docker — дополнительный вариант

Установите и запустите Docker Desktop. Создайте `.env`:

```powershell
python scripts/init_env.py
docker compose up -d --build
docker compose exec api python -m app.cli seed-demo
```

Если Python на компьютере отсутствует, скопируйте `.env.example` в `.env` и задайте непустой `DB_PASSWORD` из букв и цифр. Docker Compose собирает свою строку подключения автоматически.

API работает на `http://localhost:8002`, PostgreSQL — на `localhost:5433`. Приложение и база имеют отдельные контейнеры, сеть и том `library-booking_library_data`. Контейнеры проекта бара не используются. При старте API выполняется `alembic upgrade head`.

Обычная остановка с сохранением данных: `docker compose down`. Удалять том базы для перезапуска не требуется.

## Доступ сотрудника

Публичная регистрация всегда создаёт читателя. Поля `role` и `branch_id` в форме регистрации запрещены.

Создайте первоначального администратора; пароль запрашивается в терминале и не отображается:

```powershell
.\.venv\Scripts\python.exe -m app.cli create-admin admin@example.org
```

Для Docker: `docker compose exec api python -m app.cli create-admin admin@example.org`.

Зарегистрируйте аккаунт сотрудника через `/api/v1/auth/register`, затем назначьте ему филиал:

```powershell
.\.venv\Scripts\python.exe -m app.cli assign-staff employee@example.org 1
```

Для Docker используется тот же вызов через `docker compose exec api python`. Сотрудник не может читать, редактировать или выгружать участников другого филиала. Учётная запись первоначального администратора имеет доступ ко всем филиалам и используется для настройки системы.

## Как проверить через Swagger

1. Откройте `/docs`. Выполните `GET /api/v1/consent` и скопируйте `version`.
2. Выполните `POST /api/v1/auth/register`: имя, email, пароль от 10 символов, `privacy_consent: true` и актуальная версия согласия. Телефон необязателен.
3. Скопируйте `access_token` из ответа. Нажмите **Authorize** и вставьте сам токен.
4. Выполните `GET /api/v1/events`, затем `POST /api/v1/bookings` с `{"event_id": 1}`.
5. Повторная запись даст `409`. `GET /api/v1/bookings` покажет только ваши записи.
6. `POST /api/v1/bookings/{id}/cancel` отменит бронь и вернёт место. Повторная отмена не меняет остаток второй раз.
7. Для проверки управления войдите через `POST /api/v1/auth/login` под созданным администратором и замените токен в **Authorize**.

Регистрация сама возвращает сессию. Формат авторизации: `Authorization: Bearer <access_token>`. Сессия действует 24 часа по умолчанию; выход отзывает конкретный токен. Сервис не требует общего секретного ключа для подписания токенов.

## Основные маршруты

Все маршруты ниже начинаются с `/api/v1`.

| Метод | Путь | Назначение | Доступ |
|---|---|---|---|
| GET | `/consent` | Текст и версия согласия | Все |
| POST | `/auth/register` | Регистрация читателя | Все |
| POST | `/auth/login` | Вход | Все |
| POST | `/auth/logout` | Выход и отзыв сессии | Пользователь |
| GET | `/auth/me` | Текущий профиль | Пользователь |
| GET | `/branches`, `/categories` | Справочники для фильтров | Все |
| GET | `/events` | Афиша с фильтрами | Все |
| GET | `/events/{id}` | Карточка и остаток мест | Все, кроме черновиков |
| POST | `/bookings` | Забронировать одно место | Пользователь |
| GET | `/bookings`, `/bookings/{id}` | Свои брони | Владелец |
| POST | `/bookings/{id}/cancel` | Отмена собственной брони | Владелец |
| POST | `/admin/branches` | Создание филиала | Администратор |
| GET, POST | `/admin/events` | Список и создание событий | Сотрудник своего филиала |
| GET, PUT | `/admin/events/{id}` | Чтение и изменение события | Сотрудник своего филиала |
| PATCH | `/admin/events/{id}/status` | Публикация и смена статуса | Сотрудник своего филиала |
| GET | `/admin/events/{id}/participants` | Участники | Сотрудник своего филиала |
| GET | `/admin/events/{id}/participants/export` | CSV | Сотрудник своего филиала |
| PATCH | `/admin/events/{id}/participants/{booking_id}/attendance` | Посещение | Сотрудник своего филиала |
| GET | `/admin/stats` | Счётчики своего филиала | Сотрудник |

Списки возвращают `items`, `total`, `limit`, `offset`. По умолчанию афиша показывает события, которые ещё не закончились; `include_past=true` включает архив. Фильтры: `q`, `branch_id`, `category`, `date_from`, `date_to`, `available_only`. Брони: `scope=all|upcoming|history`.

Объекты и форматы полей полностью описаны в `/docs`, `/redoc` и `/openapi.json`. Файл `docs/openapi.json` позволяет изучать контракт без запуска сервера.

## Правила бронирования

`available_seats = capacity − количество броней со статусом confirmed`.

Создание, отмена брони, изменение вместимости, отмена события и отметка посещения используют одну блокировку строки мероприятия `SELECT … FOR UPDATE` в PostgreSQL. Проверка остатка и изменение выполняются в одной транзакции. Это предотвращает превышение вместимости при одновременных заявках и гонки с изменением события. Дополнительный частичный уникальный индекс запрещает две подтверждённые брони одного читателя на одно мероприятие.

`booking_state` показывает фактическую доступность: `draft`, `not_open`, `open`, `full`, `closed`, `completed`, `cancelled`. Период записи проверяется сервером при каждой заявке, даже если страница долго оставалась открытой.

Статусы события: `draft → published → closed → completed`, с возможностью отмены до завершения. Закрытую запись можно открыть повторно только до окончания её периода. Отменённое и завершённое событие нельзя восстановить или редактировать. Причина отмены обязательна и видна в личном кабинете.

Статусы брони: `confirmed`, `cancelled` (читатель), `event_cancelled` (организатор). `attended` — отдельное поле: `null` не отмечено, `true` посетил, `false` не посетил. Оно не освобождает место. Вместимость нельзя уменьшить ниже количества действующих броней.

Время хранится и возвращается с часовым поясом, в UTC. Запросы с датой без смещения отклоняются. Фильтры календарных дат интерпретируются в `APP_TIMEZONE` (по умолчанию `Europe/Moscow`). Сайт должен отображать время в этом часовом поясе.

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

Обычный запуск использует временные SQLite-базы только для функциональных проверок. Проверка гонок требует PostgreSQL и в обычном запуске пропускается: SQLite не обеспечивает необходимые блокировки строк.

Чтобы выполнить весь набор, создайте отдельную базу `library_booking_test` и задайте:

```powershell
$env:LIBRARY_TEST_DATABASE_URL="postgresql+asyncpg://library:your-password@localhost:5433/library_booking_test"
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты разрешены только в базе с точным именем `library_booking_test`. Каждый тест создаёт собственную случайную схему и удаляет только её. Рабочую базу они не очищают. В CI используется отдельный PostgreSQL.

## Границы первой версии

Это версия для проверки на практике. Текст согласия демонстрационный: перед эксплуатацией библиотека утверждает свой текст в `app/consent.py` и меняет его версию. Восстановление пароля, подтверждение email, внешние уведомления и список ожидания в эту версию не входят. Возрастная маркировка информационная; дата рождения не собирается. «Один читатель» определяется одним аккаунтом, без проверки читательского билета.

Возврат к выбранному мероприятию после входа, повтор пароля в форме и диалог подтверждения отмены реализуются будущим фронтендом; сервер предоставляет необходимые методы и повторно проверяет места. Для эксплуатации нужны HTTPS, резервное копирование PostgreSQL и ограничение частоты входа/регистрации на уровне сервера размещения. Локальная конфигурация слушает только `127.0.0.1`.
